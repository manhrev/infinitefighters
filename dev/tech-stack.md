# Tech Stack Decision

Status: accepted (2026-10-15). Target art style: 2D pixel-art platformer ("Task Vo Tan"). MVP scope fixed in `game-scenario.md` (one co-op level, 1–5 players).

## Goal

Browser-based multiplayer game, hosted on a local machine, played by colleagues over the office LAN. Nothing to install for players: they open a URL.

## Backend: single Go binary

- **Go 1.27.**
- **HTTP:** standard library `net/http` with the 1.22+ `ServeMux` routing. No web framework; only two routes are needed (static files and `/ws`).
- **Realtime transport:** WebSocket via `github.com/coder/websocket` (maintained successor of `nhooyr.io/websocket`, context-aware). This is the only third-party dependency.
- **Game model:** authoritative server. Clients send inputs only; the server owns all game state and broadcasts snapshots. Prevents clients from cheating by changing state locally.
- **Simulation:** a single room (one per server), run by one goroutine. Physics and game logic tick at a fixed 60 Hz; snapshots are broadcast at 30 Hz.
- **Connections:** each client gets a read goroutine and a write goroutine with a buffered send channel. A client whose buffer fills is disconnected so it cannot stall the room.
- **State:** in memory only. No database. If persistence is needed later (scores, accounts), add SQLite via `modernc.org/sqlite` (pure Go, no cgo).
- **Wire format:** JSON. Easy to inspect in browser DevTools. Switch to a binary format only if profiling shows bandwidth is a problem.

## Frontend: served by the same binary

- **Language/build:** TypeScript, built with Vite.
- **Rendering:** Phaser 3 (WebGL, `pixelArt: true`). Chosen after seeing the target art: a 2D pixel-art platformer ("Task Vo Tan") with sprite animations, tilemaps, parallax backgrounds and many projectiles. Phaser is used for rendering, animation, input and effects only; its physics does not decide game outcomes.
- **Levels:** built in Tiled, exported as JSON. The Go server loads the same JSON to get the collision tiles.
- **Physics:** the Go server runs its own simple platformer physics (gravity, AABB vs tile collision). MVP has no client-side prediction: LAN latency is about 1–5 ms, so clients only interpolate snapshots. Add prediction only if movement feels laggy in playtests.
- **Art assets:** need real sprite sheets (fixed frame size, transparent background, consistent pixel scale per animation), not concept art. Draw or clean up in Aseprite.
- **Client role:** read input, send it to the server, interpolate between server snapshots, render.
- **Scaling:** 1280 × 720 reference viewport, scaled to fit the window (Phaser `Scale.FIT`), letterbox for other aspect ratios. Nearest-neighbour filtering (`pixelArt: true`); non-integer scales give slightly uneven pixel sizes. Changed on 2026-10-15: first from integer-only zoom (the game was too small on laptops), then from 1920 × 1080 to 1280 × 720 for a closer, crowded arena like the concept.
- **Audio:** Phaser Web Audio, files from `assets/audio/manifest.json` (OGG with MP3 fallback). Combat sounds play once per server event counter, never per snapshot; loops (music, wind-clock, hotfix zone) are owned by an id and stop when the match ends. Lobby music plays outside Phaser. Volume settings are stored per browser.
- **Delivery:** the Vite build output is embedded into the Go binary with `//go:embed`. One binary to ship and run.

## LAN hosting

- Server listens on `0.0.0.0:8080`.
- On startup, the server prints `http://<LAN-IP>:8080` for colleagues to open.
- macOS shows a firewall prompt the first time the binary listens; allow it.
- Plain HTTP. Acceptable on a trusted office LAN. A 4-character room code, printed at startup, is required to join.

## Dev workflow

- `vite dev` serves the frontend with hot reload and proxies `/ws` and `/levels` to the Go server.
- `make build` (in `infinitefighters-backend/`) runs the Vite build into `infinitefighters-backend/web/`, then `go build`, producing one binary, `./infinitefighters`.
- Server flags: `-addr :8080`, `-code ABCD` (fixed room code), `-deadline 10m`, `-boss-hp 120` (boss HP with one player, for playtests), `-hard` (hard mode), `-party` (Start goes straight to the party PvP phase).
- Browser tests: open the page with `?debug` to read the live match state as `__world` in the console.
- Levels: `infinitefighters-backend/levels/sprint.json` (boss arena) and `party.json` (party PvP hall), Tiled format, generated by `scripts/gen_levels.py`. Collision comes from the tileset property `collision = solid | oneway`; object types `spawn`, `boss`, `coffee`, `safe`, `atm`, `respawn` and `prop` (decoration only).
- Party phase: `party.go` runs it separately from the co-op rules (its own damage, skills, money and ATMs), reusing physics and input. A boss win switches the room to `party.json`; the start message carries `mode` and the client builds a fresh scene.

## Deliberately out of scope (for now)

Accounts, database, Docker, TLS, external matchmaking service. Revisit only if a real need appears.

## Session rules (MVP)

- **Lobby:** one room per server. Player enters name and room code; first player in is host and picks the level: “Đường Đua Sprint” (boss, co-op) or “Anh em cây khế” (party PvP). The start message carries `level`.
- **Reconnect:** on join, the server issues a session token, stored in the browser `localStorage`. If the socket drops, the player slot is kept and the character is frozen and invulnerable. Reopening the page with the same token resumes the same character. If every player is disconnected, the match pauses.
- **Boss scaling:** computed once at match start from every player slot, away players included. A restart after a loss keeps it.
- **Lose conditions:** all connected players down, or the DEADLINE timer runs out. The server shows why for 4 s, then restarts the level.
- **Win:** boss HP reaches 0. After 6 s everyone returns to the lobby; away players lose their slot. The host can start again.
- **Joining:** at most 5 players. New players can join only in the lobby; during a match only a token reconnect is accepted. Opening the same token in a second tab closes the first.
